# 2-5. 리포지터리(Repository)로 데이터베이스 관리하기

## Repository란?

Spring Data JPA가 제공하는 인터페이스로, SQL을 직접 작성하지 않고도 데이터베이스를 쉽게 조회하고 관리할 수 있다.

```java
import org.springframework.data.jpa.repository.JpaRepository;

public interface QuestionRepository extends JpaRepository<Question, Integer> {

}
```

### JpaRepository<엔티티, 기본키 타입>

- `Question` : 관리할 엔티티
- `Integer` : 기본키(id)의 자료형

JpaRepository를 상속하면 기본 CRUD 기능을 바로 사용할 수 있다.

- 데이터 저장 (`save`)
- 전체 조회 (`findAll`)
- 단건 조회 (`findById`)
- 삭제 (`delete`)
- 개수 조회 (`count`)

# JUnit 설정

Repository를 테스트하려면 JUnit 의존성이 필요하다.

```gradle
testImplementation 'org.junit.jupiter:junit-jupiter'
testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
```

# @Autowired를 이용한 객체 주입

테스트 코드에서는 Repository를 직접 생성하지 않는다.

```java
@Autowired
private QuestionRepository questionRepository;
```

`@Autowired`를 사용하면 스프링이 Repository 객체를 자동으로 생성하여 주입한다.

### 객체 주입 방식

1. `@Autowired` 필드 주입
2. Setter 주입
3. 생성자 주입 ⭐ (권장)

실제 프로젝트에서는 **생성자 주입**을 사용하는 것이 좋다.

이유

- 불변 객체 생성 가능
- 순환 참조 문제를 쉽게 발견 가능
- 테스트 작성이 편리

단, **JUnit 테스트에서는 생성자 주입을 지원하지 않기 때문에 `@Autowired`를 사용하는 경우가 많다.**

# JpaRepository 주요 메서드

## 1. save()

데이터 저장 또는 수정

```java
questionRepository.save(question);
```

---

## 2. findAll()

모든 데이터를 조회한다.

```java
List<Question> list = questionRepository.findAll();
```

---

## 3. findById()

기본키(id)로 조회한다.

```java
Optional<Question> question = questionRepository.findById(1);
```

반환 타입이 `Optional`인 이유는 해당 데이터가 존재하지 않을 수도 있기 때문이다.

---

## 4. findBySubject()

Subject 컬럼으로 조회한다.

```java
Question question =
        questionRepository.findBySubject("제목");
```

Spring Data JPA가 메서드 이름을 분석하여 SQL을 자동 생성한다.

```sql
SELECT *
FROM question
WHERE subject = ?
```

---

## 5. findBySubjectAndContent()

Subject와 Content가 모두 일치하는 데이터를 조회한다.

```java
Question question =
        questionRepository.findBySubjectAndContent(
                "제목",
                "내용"
        );
```

자동 생성되는 SQL

```sql
SELECT *
FROM question
WHERE subject = ?
AND content = ?
```

---

## 6. findBySubjectLike()

LIKE 검색을 수행한다.

```java
List<Question> list =
        questionRepository.findBySubjectLike("%스프링%");
```

예상 SQL

```sql
SELECT *
FROM question
WHERE subject LIKE '%스프링%';
```

# @Transactional

```java
@Transactional
```

트랜잭션(Transaction)을 적용하는 애너테이션이다.

하나의 작업을 하나의 단위로 처리하며,

- 모두 성공하면 **Commit**
- 하나라도 실패하면 **Rollback**

된다.

예를 들어 게시글 저장과 답변 저장을 함께 수행할 때

```text
게시글 저장
답변 저장
```

둘 중 하나라도 실패하면 모든 작업이 취소되어 데이터의 일관성을 유지한다.

또한 Lazy Loading으로 조회되는 객체를 사용할 때도 자주 사용된다.

---

# 핵심 정리

- `JpaRepository`를 상속하면 CRUD 기능을 바로 사용할 수 있다.
- Repository 테스트에는 JUnit이 필요하다.
- 테스트 코드에서는 `@Autowired`를 사용하지만 실제 프로젝트에서는 생성자 주입을 권장한다.
- 메서드 이름만으로 조회 메서드를 자동 생성할 수 있다.
- `Optional`은 조회 결과가 없을 가능성을 고려하기 위해 사용한다.
- `@Transactional`은 여러 작업을 하나의 트랜잭션으로 처리하여 데이터의 일관성을 보장한다.
