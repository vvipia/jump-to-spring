# 2-1장 스프링 부트 프로젝트 구조

## 1. 프로젝트명 + `Application.java`

- 스프링 부트 애플리케이션의 시작점(Entry Point)
- `main()` 메서드가 존재하는 클래스
- 반드시 `@SpringBootApplication` 애너테이션이 있어야 스프링 부트가 실행된다.

> 📌 핵심
> - 프로젝트 실행 시 가장 먼저 실행되는 클래스
> - 컴포넌트 스캔과 자동 설정이 시작된다.

---

## 2. `src/main/resources`

- 자바 코드가 아닌 리소스 파일을 저장하는 공간
- HTML, CSS, JavaScript, 설정 파일 등을 보관한다.

예시
- `application.properties`
- `templates`
- `static`

---

## 3. `src/main/resources/templates`

- 화면(View)을 만드는 템플릿 파일을 저장하는 디렉터리
- HTML 안에서 자바 객체의 데이터를 출력할 수 있다.
- 보통 Thymeleaf 템플릿을 사용한다.

> 📌 Controller → Model → Template → 브라우저

---

## 4. `src/main/resources/static`

- 정적인(Static) 파일을 저장하는 공간
- 브라우저가 그대로 다운로드하여 사용하는 파일들

예시
- CSS
- JavaScript
- 이미지
- 아이콘

---

## 5. `application.properties`

- 프로젝트의 환경 설정 파일
- 실행에 필요한 각종 설정을 작성한다.

대표적인 설정
- 서버 포트
- 데이터베이스 연결
- 로그 레벨
- H2 Console
- JPA 설정

---

## 6. `build.gradle`

- Gradle이 사용하는 빌드 설정 파일
- 프로젝트에서 사용할 라이브러리(Dependency)를 관리한다.
- Java 버전, 플러그인, 빌드 설정 등을 작성한다.

예시
- Spring Web
- Spring Data JPA
- Lombok
- H2 Database
