# 1. 질문 등록 기능 구현

## 질문 등록 화면 이동

질문 목록에서 **질문 등록하기** 버튼을 클릭하면

```
GET /question/create
```

요청이 발생한다.

Controller에서는 등록 화면(question_form.html)을 반환한다.

```java
@GetMapping("/create")
public String questionCreate() {
    return "question_form";
}
```

---

## 질문 저장

저장하기 버튼을 누르면

```
POST /question/create
```

요청이 발생한다.

Controller는 입력값을 전달받아 Service를 호출하고, 저장 후 목록 페이지로 이동한다.

```java
@PostMapping("/create")
public String questionCreate(...) {
    questionService.create(...);
    return "redirect:/question/list";
}
```

# 2. MVC 흐름

질문 등록 요청은 다음과 같은 흐름으로 동작한다.

```
사용자
    ↓
HTML Form
    ↓
Controller
    ↓
Service
    ↓
Repository
    ↓
Database
```

Controller는 요청을 처리하고,

Service는 비즈니스 로직을 수행하며,

Repository가 실제 DB와 통신한다.

# 4. Validation

입력값이 비어있거나 조건에 맞지 않는 경우 저장되지 않도록 검증하는 기능이다.

build.gradle

```gradle
implementation 'org.springframework.boot:spring-boot-starter-validation'
```

대표적으로 사용하는 애너테이션

| 애너테이션 | 설명 |
|------------|------|
| @NotEmpty | 빈 문자열 또는 Null 허용 안 함 |
| @Size | 문자열 길이 제한 |
| @Min | 최소값 제한 |
| @Max | 최대값 제한 |

---

# 5. Form 클래스

입력값을 하나의 객체로 관리하기 위해 Form 클래스를 사용한다.

```java
@Getter
@Setter
public class QuestionForm {

    @NotEmpty(message = "제목은 필수항목입니다.")
    @Size(max = 200)
    private String subject;

    @NotEmpty(message = "내용은 필수항목입니다.")
    private String content;
}
```

### 사용하는 이유

기존 방식

```java
@RequestParam String subject
@RequestParam String content
```

보다

```java
QuestionForm questionForm
```

처럼 객체 하나로 관리하는 것이 유지보수에 훨씬 유리하다.

---

# 6. @Valid와 BindingResult

```java
@PostMapping("/create")
public String questionCreate(
        @Valid QuestionForm questionForm,
        BindingResult bindingResult) {

    if(bindingResult.hasErrors()) {
        return "question_form";
    }

    questionService.create(
        questionForm.getSubject(),
        questionForm.getContent());

    return "redirect:/question/list";
}
```

## @Valid

Form 객체에 작성한 Validation을 실행한다.

## BindingResult

Validation 결과를 저장한다.

```java
bindingResult.hasErrors()
```

- true → 오류 발생
- false → 저장 진행

> **주의**
>
> `BindingResult`는 반드시 `@Valid` 바로 뒤에 위치해야 한다.

# 7. th:object와 th:field

```html
<form th:object="${questionForm}">
```

Form과 QuestionForm 객체를 연결한다.

---

```html
<input th:field="*{subject}">
```

```html
<textarea th:field="*{content}">
```

### 장점

- id 자동 생성
- name 자동 생성
- value 자동 유지

Validation 실패 후에도 사용자가 입력했던 값이 그대로 유지된다.

---

# 8. 오류 메시지 출력

Validation 실패 시

```html
<div th:if="${#fields.hasAnyErrors()}">
```

를 이용해 오류 메시지를 출력한다.

```html
<div th:each="err : ${#fields.allErrors()}"
     th:text="${err}">
</div>
```

---

# 9. 공통 템플릿

오류 출력 코드는 여러 화면에서 반복되므로

```
form_errors.html
```

파일로 분리하여 재사용한다.

```html
<div th:replace="~{form_errors :: formErrorsFragment}"></div>
```

`th:replace`를 사용하면 공통 템플릿을 현재 위치에 삽입할 수 있다.

---

# 핵심 정리

- GET 요청은 화면을 반환한다.
- POST 요청은 데이터를 저장한다.
- Controller → Service → Repository 구조를 따른다.
- Form 객체를 이용해 입력값을 관리한다.
- Validation으로 입력값을 검증한다.
- `@Valid`가 Validation을 실행한다.
- `BindingResult`가 검증 결과를 저장한다.
- `th:field`를 사용하면 입력값이 유지된다.
- 반복되는 HTML은 `th:replace`를 사용해 공통 템플릿으로 관리한다.
