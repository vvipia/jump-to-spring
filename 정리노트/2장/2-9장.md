## 2-9장 서비스 활용하기

### 서비스(Service)란?

서비스(Service)는 **비즈니스 로직(데이터 처리)** 을 담당하는 클래스이다.

프로젝트 규모가 커질수록 컨트롤러에서 `Repository`를 직접 호출하지 않고, **중간에 Service를 거쳐 데이터를 처리**하는 구조를 사용한다.

```
Controller → Service → Repository → Database
```

---

### 서비스를 사용하는 이유

#### 1. 역할 분리(모듈화)

컨트롤러는 **요청과 응답 처리**만 담당하고,

서비스는 **데이터 조회 및 비즈니스 로직**을 담당하도록 역할을 분리할 수 있다.

이를 통해 코드의 재사용성과 유지보수성이 향상된다.

#### 2. DTO로 변환하기

서비스에서는 조회한 엔티티(Entity)를 DTO(Data Transfer Object)로 변환하여 컨트롤러에 전달할 수 있다.

DTO를 사용하면 엔티티를 외부에 직접 노출하지 않아도 되므로 민감한 데이터 노출을 방지할 수 있다.

---

### QuestionService 작성

```java
@RequiredArgsConstructor
@Service
public class QuestionService {

    private final QuestionRepository questionRepository;

    public List<Question> getList() {
        return this.questionRepository.findAll();
    }
}
```

#### `@Service`

- 해당 클래스를 **서비스 클래스**로 스프링에 등록한다.
- 스프링이 객체를 생성하고 관리(Bean 등록)한다.

#### `@RequiredArgsConstructor`

- `final` 필드를 매개변수로 받는 생성자를 자동 생성한다.
- 스프링이 `QuestionRepository` 객체를 생성자에 주입한다.

#### `getList()`

```java
public List<Question> getList() {
    return this.questionRepository.findAll();
}
```

- `QuestionRepository`를 이용하여 모든 질문을 조회한다.
- 조회한 `List<Question>`을 컨트롤러에 반환한다.

---

### 변경 전

컨트롤러가 Repository를 직접 호출

```text
Controller
      │
      ▼
Repository
      │
      ▼
Database
```

```java
List<Question> questionList = questionRepository.findAll();
```

---

### 변경 후

컨트롤러는 Service만 호출

```text
Controller
      │
      ▼
Service
      │
      ▼
Repository
      │
      ▼
Database
```

```java
List<Question> questionList = questionService.getList();
```

서비스 내부에서 `Repository`를 호출하여 데이터를 조회하므로, 컨트롤러는 요청과 응답 처리에만 집중할 수 있다.
