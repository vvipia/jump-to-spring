# 2-6. 도메인별로 분류하기

## 도메인이란?

도메인(Domain)은 프로그램이 해결하려는 업무 영역이나 기능 단위를 의미한다.

게시판 프로젝트에서는 대표적으로 다음과 같은 도메인이 있다.

| 도메인 이름 | 패키지 이름 | 설명 |
|---|---|---|
| `question` | `com.mysite.sbb.question` | 게시판 질문과 관련된 자바 파일 모음 |
| `answer` | `com.mysite.sbb.answer` | 게시판 답변과 관련된 자바 파일 모음 |
| `user` | `com.mysite.sbb.user` | 사용자와 관련된 자바 파일 모음 |

---

## 도메인별 패키지 구조

프로젝트의 자바 파일을 기능별로 구분하면 다음과 같은 구조가 된다.

```text
com.mysite.sbb
├── question
│   ├── Question.java
│   ├── QuestionController.java
│   ├── QuestionService.java
│   └── QuestionRepository.java
│
├── answer
│   ├── Answer.java
│   ├── AnswerController.java
│   ├── AnswerService.java
│   └── AnswerRepository.java
│
└── user
    ├── SiteUser.java
    ├── UserController.java
    ├── UserService.java
    └── UserRepository.java
```

질문과 관련된 클래스는 `question` 패키지에 넣고, 답변과 관련된 클래스는 `answer` 패키지에 넣는 방식이다.

---

## 계층별 분류 방식

프로젝트를 다음과 같이 클래스 역할에 따라 분류할 수도 있다.

```text
com.mysite.sbb
├── controller
│   ├── QuestionController.java
│   └── AnswerController.java
├── service
│   ├── QuestionService.java
│   └── AnswerService.java
├── repository
│   ├── QuestionRepository.java
│   └── AnswerRepository.java
└── entity
    ├── Question.java
    └── Answer.java
```

이 구조에서는 모든 Controller, Service, Repository, Entity가 각각 같은 패키지에 모인다.

프로젝트가 작을 때는 구조가 단순하지만, 기능이 많아지면 하나의 도메인에 관련된 파일이 여러 패키지에 흩어질 수 있다.

---

## 도메인별 분류 방식

```text
com.mysite.sbb
├── question
│   ├── Question.java
│   ├── QuestionController.java
│   ├── QuestionService.java
│   └── QuestionRepository.java
└── answer
    ├── Answer.java
    ├── AnswerController.java
    ├── AnswerService.java
    └── AnswerRepository.java
```

도메인별 분류에서는 하나의 기능과 관련된 파일을 같은 패키지에 모아 관리한다.

예를 들어 질문 기능을 수정할 때는 `question` 패키지만 확인하면 된다.

---

## 도메인별로 분류하는 이유

### 1. 관련 코드를 빠르게 찾을 수 있다

질문 기능에 문제가 발생하면 `question` 패키지만 확인하면 된다.

```text
question
├── Question.java
├── QuestionController.java
├── QuestionService.java
└── QuestionRepository.java
```

---

### 2. 코드의 역할과 구조를 이해하기 쉽다

패키지 이름만 봐도 어떤 기능을 담당하는 코드인지 알 수 있다.

```text
question → 질문 기능
answer   → 답변 기능
user     → 사용자 기능
```

---

### 3. 유지보수가 편리하다

하나의 도메인과 관련된 코드가 같은 위치에 모여 있으므로 기능을 수정하거나 확장하기 쉽다.

예를 들어 질문 검색 기능을 추가한다면 주로 `question` 패키지 안에서 작업하게 된다.

---

### 4. 프로젝트가 커져도 관리하기 쉽다

기능이 추가될 때 새로운 도메인 패키지를 만들 수 있다.

```text
com.mysite.sbb
├── question
├── answer
├── user
├── comment
├── category
└── notification
```

각 도메인이 분리되어 있으므로 기능이 많아져도 코드 구조가 비교적 명확하게 유지된다.

---

## 핵심 정리

- 도메인은 프로그램의 업무 영역 또는 기능 단위를 의미한다.
- 질문, 답변, 사용자처럼 관련된 기능별로 패키지를 나눌 수 있다.
- 하나의 도메인과 관련된 Entity, Controller, Service, Repository를 같은 패키지에 모은다.
- 도메인별 분류는 코드 탐색, 기능 수정, 유지보수에 유리하다.
- 프로젝트의 규모가 커질수록 도메인별 패키지 구조의 장점이 커진다.
